## 玩法概述

你是"启元一号"托卡马克的**当班运行总工程师**。一局游戏共 **4 轮**，每轮：

1. **听取四份专家简报** —— 四个子系统负责人各有立场偏见，会**隐瞒**或**夸大**信息。
2. **交叉验证仪表** —— 简报话术常与客观仪表读数矛盾，需识破谎言。
3. **拖放经费修复** —— 把有限的经费代币（每轮 100 单位）拖到装置四部位投资。
4. **提交结算** —— 在正确部位投足修复阈值即识破根因，推进下一轮。

四轮故障并非孤立，而是源自**三个根本原因**的耦合表现：

| 根本原因 | 表象部位 | 修复部位 | 关联专家 |
|----------|----------|----------|----------|
| 磁体电源老化 | 环向场下滑 | 环向场磁体线圈 | 磁体工程师（隐瞒） |
| 第一壁微裂纹 | 壁温升高 | 第一壁内衬 | 材料负责人（隐瞒） |
| 氚提取泵效率下降 | 氚自持率走低 | 氚增殖包层 | 氚循环工程师（夸大） |

### 四位性格化专家

- **磁体工程师**（老派稳妥）：倾向全投磁体，隐瞒磁体异常。
- **材料与第一壁负责人**（激进冒险）：夸大新材料，隐瞒微裂纹。
- **氚循环工程师**（悲观预警）：永远喊"氚不够"，夸大贫化。
- **等离子体物理师**（理想主义）：推崇算法优化，轻视硬件投入。

### 结局矩阵

最终结局由 **2D 矩阵**决定，共 **12 种**：

- 横轴：最终 Q 值区间（`<1` / `1~1.1` / `>1.1`）
- 纵轴：识破的根本原因数量（`0` / `1` / `2` / `3`）

从「全盘失守」到「聚变之星」，每种结局给出不同科普总结，鼓励重玩。

### 难度模式

| 模式 | 限时 | 仪表噪声 | 简报可疑点高亮 | 建议提示 | 历史日志 |
|------|------|----------|----------------|----------|----------|
| **新手 / 科普** | 不限时 | 无 | ✓ 染红 | ✓ 角标 | — |
| **总工** | 每轮 300/240/180s | 有 | — | — | ✓ 可查阅 |
| **自定义** | 240s | 微 | — | — | ✓ |

## 视听表现

- **实时托卡马克剖面**：中控台中央动态绘制环形装置（真空室、环向场线圈、等离子体环、磁场线），随约束稳定度实时切换三档运行态——蓝白炽热稳定 / 橙色临界抖动 / 暗红破裂紊乱。
- **破裂报警**：约束稳定度跌破临界（`disruption_threshold`）时，装置进入破裂动画（线圈失超变暗、第一壁烧蚀火花），同时触发报警音、顶部脉动预警横幅与破裂科普弹窗；恢复后自动解除。
- **结局运行动画**：进入结局先全屏播放对应命运的装置动画（稳态长脉冲 / 勉强维持 / 等离子体破裂），再让结局卡片滑入。可点击 / 按键跳过。
- **背景音乐**：主菜单（明亮）、中控台（克制紧张）、结局（舒缓）三段无缝循环原创配乐，纯程序合成、可调音量。
- **等离子体粒子**：色调严格对应约束稳定度（炽热蓝白 ↔ 恶化暗红），粒子数性能可配。

> 所有视觉均为程序矢量绘制 / 粒子，**无图片依赖**；音乐为程序合成的原创音轨，无版权风险。

## 技术栈

- **引擎**：Godot 4.6（Forward+ 渲染器）
- **语言**：GDScript（100%）
- **特效**：GPUParticles2D 等离子体粒子 + Node2D `_draw` 程序矢量绘制（托卡马克剖面 / 结局动画，无图片依赖）
- **音频**：程序合成的原创 BGM（无缝循环 WAV）+ 事件音效，独立音量、跨场景持续
- **数据**：全部科普文本 / 故障逻辑 / 专家台词 / 结局文案外置 `res://data/*.json`
- **存档**：Godot `ConfigFile`（存档 / 设置 / 成就，纯 `user://` 本地）
- **导出目标**：Windows / macOS / Linux / HTML5

## 项目结构

```
res://
├── project.godot
├── data/                      # 全部配置（JSON，非程序员可改）
│   ├── experts.json           # 四位专家性格与立场
│   ├── faults.json            # 故障树：根因→四轮表象
│   ├── rounds.json            # 仪表基准与每轮限时
│   ├── briefings.json         # 专家简报话术（含隐瞒/夸大标记）
│   ├── endings.json           # 12 结局矩阵文案
│   ├── difficulty.json        # 三种难度参数
│   ├── balance.json           # 核心数值平衡（公式系数、故障影响）
│   ├── popups.json            # 浮动科普标签
│   ├── kb_glossary.json       # 手册：科普词条
│   └── kb_timeline.json       # 手册：成果/辟谣/就业
├── scripts/
│   ├── autoload/              # 单例：DataManager / GameState / SaveManager / AudioManager
│   ├── core/                  # 业务：FusionEngine / FaultTree / BriefingSystem / EndingResolver
│   └── ui/                    # 视图脚本（含 TokamakAnimation / PlasmaCore / SettingsPanel）
├── scenes/
│   ├── menu/                  # 主菜单（含设置面板入口）
│   ├── control_room/          # 中控台主场景（实时托卡马克 + 破裂报警）
│   ├── components/            # Gauge / BudgetToken / DropZone / BriefingCard / PopupTag
│   ├── panels/                # ManualPanel / LogPanel / EndingPanel / SettingsPanel
│   └── fx/                    # PlasmaCore 粒子 / TokamakAnimation 装置动画
└── assets/
    └── audio/                 # 程序合成 BGM（bgm_menu / bgm_control / bgm_ending）
```

**架构约定**：业务逻辑下沉 `scripts/core/`（纯函数式，便于测试与复用）；视图脚本只管交互与显示；所有数值禁止硬编码，集中于 `data/balance.json`。

## 运行与构建

### 在编辑器中运行

1. 用 **Godot 4.6+** 打开本项目目录（含 `project.godot`）。
2. 按 **F5** 运行，或点击右上角播放按钮。

### 命令行运行（无需打开编辑器）

```bash
# Windows（bash）
"<Godot可执行文件>" --path . 
# 仅导入资源后退出（首次校验）
"<Godot可执行文件>" --headless --path . --import
```

### 导出

桌面三平台 + HTML5。HTML5 端建议在设置中将粒子质量降为 `low` 以保证流畅。导出产物完全离线，可直接上传 GitHub Pages 等静态托管。

> 导出需安装对应 Godot 版本的 **导出模板**（编辑器 → 项目 → 导出 → 管理导出模板）。

**Web 导出关键配置**（`export_presets.cfg` 已设好）：

| 选项 | 值 | 原因 |
|------|----|------|
| `线程支持 / thread_support` | **关** | 开启需 `SharedArrayBuffer` → 需 COOP/COEP 响应头，GitHub Pages 无法提供 |
| 入口文件名 | `index.html` | ASCII 命名，避免中文名 URL 编码导致 `Failed to fetch`；Pages 自动加载 |
| 默认字体 | 思源黑体（SIL OFL） | 内置字体无中文字形，Web 端取不到系统字体，必须随包内置 |

> 本地预览：进入导出目录执行 `python -m http.server`，浏览器开 `http://localhost:8000/`（**勿用 `file://` 双击打开**，否则 `Failed to fetch`）。

### 自动部署（CI/CD）

仓库已配置 GitHub Actions（`.github/workflows/deploy-pages.yml`）：**推送到 `main` 分支即自动**用 Godot 4.6.3 headless 构建 Web 导出并发布到 GitHub Pages。

- 首次使用需在仓库 **Settings → Pages → Source** 选择 **GitHub Actions**。
- 构建产物经 Pages 制品流水线部署，无需将 `h5/` 提交进仓库。
- Godot 与导出模板（约 600MB）首次后缓存，后续构建跳过下载。

## 内容配置（无需编程）

所有文本与数值外置 JSON，物理/文案同学可直接编辑 `res://data/` 下文件，**无需接触引擎代码**：

- 改专家台词 → `briefings.json`
- 改科普词条 → `kb_glossary.json` / `kb_timeline.json`
- 改故障参数 → `faults.json`
- 调数值平衡（Q值手感、故障强度）→ `balance.json`
- 加结局文案 → `endings.json`

启动时 `DataManager` 会自动加载并校验所有配置，缺字段 / 格式错会在控制台明确报错。标有 `_todo` / `_comment` 的字段为待补充占位，可安全填充或留空。
